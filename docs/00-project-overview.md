# 00. 프로젝트 개요

## 사업 배경 (시장조사 결론 요약)

정부·LH·SH 등의 주거·복지 혜택(공공임대, 특별공급, 청년월세 등)과 청약 정보가 여러
기관에 흩어져 있고, 조건이 복잡해서 본인이 뭘 받을 수 있는지 알기 어렵다는 문제에서
출발.

시장조사(2026-09) 결론:
- 단순 "공고 모음 + AI 요약" 앱은 이미 경쟁자가 많음(웰로, 집다움, 주거나침반 등) —
  차별화가 약함.
- 반면 "개인 프로필 기반으로 신청 가능 여부를 정밀 판정하고, 판정 근거를 보여주는"
  Eligibility Engine 영역은 아직 지배적 서비스가 없음.
- 핵심 자산은 앱이 아니라 **정책 조건을 기계 판정 가능하게 구조화한 Rule Engine**이며,
  장기적으로는 이 판정 로직 자체를 은행·카드·통신사에 API로 공급하는 B2B2C 모델이
  B2C 앱보다 사업성이 높다고 판단.

## MVP 타깃 (v0.1 설계 문서 기준)

- 사용자: 서울·경기 25~39세 무주택 청년·예비신혼·신혼부부
- 기관: LH + SH + 서울시 중심 (이후 GH/HF/HUG 확대)
- 상품: 행복주택, 청년/신혼 임대, 장기전세, 공공분양, 특별공급, 청년월세,
  임차보증금/이자 지원
- 정책 수: 초기 20건 → 이후 50~100건
- 채널: 반응형 Web MVP 우선 (앱은 PMF 확인 후)

## 제품 한 문장 정의

사용자의 프로필을 저장해 두고 신규 정책·공고가 들어올 때마다 Rule Engine이 자동으로
재판정하여 "신청 가능 / 추가정보 필요 / 신청 불가"를 근거와 함께 보여주는 서비스.

## 6대 설계 원칙 (v0.1 문서에서 확정)

- 정확성 > 공고 수
- Rule Engine > 자체 LLM
- 근거 추적성 > 자연스러운 AI 답변
- Progressive Profiling > 과도한 초기 개인정보 수집
- Human-in-the-loop > 무검수 자동화
- Web MVP > 초기 네이티브 앱

## 지금 이 리포지토리가 다루는 범위

이 리포지토리는 위 전체 기획 중 **"MVP0: Rule Engine이 실제로 3개 실제 공고에 대해
정확히 판정하는가"**를 검증하는 단계까지의 산출물이다. Progressive Profiling UI,
데이터 자동수집 파이프라인, 관리자 검수 화면 등은 아직 이 리포지토리 범위 밖이다.
